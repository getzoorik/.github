# Contributing to Zoorik

Thanks for helping. This guide covers every public `getzoorik` repository that has no guide of its own.

## Open an issue

- Search the open issues first. Someone may have reported it already.
- Pick the bug report or the feature request form and fill it in. For a bug, say what you did, what you expected and what happened, and include the version you ran.
- Remove tokens, keys and other secrets from anything you paste.
- For a question about using Zoorik, start with the docs at [zoorik.com/docs](https://zoorik.com/docs).
- Found a security problem? Do not open an issue. Follow [SECURITY.md](SECURITY.md) instead.

## Send a pull request

1. Fork the repository and create a branch from `main`.
2. Make one change per pull request. Small pull requests are easier to review and land sooner.
3. Run the checks the repository's README describes.
4. Open the pull request and fill in the template: what you changed, why, and how you tested it.

For a big change, open an issue first so we can agree on the approach before you spend time on it.

You do not need to sign off your commits or sign a contributor agreement. Our public repositories are licensed under Apache-2.0 (copyright Zoorik Private Limited), and what you send is licensed the same way, as section 5 of the license says.

## Be kind

Be patient, assume good intent and keep feedback about the work, not the person. Everyone here follows our [Code of Conduct](CODE_OF_CONDUCT.md). To report a problem, write to [founders@zoorik.com](mailto:founders@zoorik.com).
